# qloo_gateway — conventions
The only service that talks to Qloo. Holds one `qloo mcp` child process (stdio) via `@modelcontextprotocol/sdk`, passing `env: process.env` so `QLOO_API_KEY` reaches it.
- Pure modules (`validate`, `scoring/*`, `geo/*`, `claims/*`, `extract`) have no I/O; test them directly.
- I/O modules take injected dependencies (`McpLike`, `FirestoreLike`, `now()`, `sleep()`); tests pass fakes. Never hit Qloo or GCP from unit tests.
- Cache: L1 in-memory LRU + L2 Firestore `qloo_cache`, TTL on `expireAt`.
- Every Qloo call goes through `resilientCall` (validate → cache → budget → mcp → retry → stale fallback).
- Imports use `.js` suffixes (NodeNext ESM).
- Deploy: container (Dockerfile) to Cloud Run, us-central1, `qloo-gateway-sa`, `--no-allow-unauthenticated`, `--min-instances=1`. `QLOO_API_KEY` from Secret Manager secret `qloo-api-key`.

## Build & deploy
- Local image check (from worktree root): `docker build -t qloo-gateway cloud_run/qloo_gateway && docker run --rm qloo-gateway qloo --version`
- The hackathon server (`https://hackathon.api.qloo.com`) is used through `QLOO_BASE_URL` and `QLOO_TRUSTED_BASE_URL` (both set by `deploy.sh`, overridable via `QLOO_BASE_URL` in the environment); for local runs set both to the same URL before starting. The gateway logs the active base URL (never a key) at startup.

## Narrative
One Gemini call per playbook via Vertex REST (ADC token from `google-auth-library`). Claims are verified by `claims/verify.ts`; unverified ones are returned as `removed` with a reason. Besides the declared `entities[]`/`numbers[]`, the displayed `text` is checked: every numeric token (decimals, `%`, thousands separators) must be supported by a declared number, and every declared entity name must appear in the text. Undeclared proper nouns in the text remain uncheckable. Results are cached 7 d under tool `gemini_narrative`. Ceilings: 20 per session (in memory) and `GEMINI_DAILY_CEILING` (default 300) per day, persisted in Firestore doc `gemini_usage/<YYYY-MM>` (with `QLOO_USAGE_BACKEND=firestore`) so restarts and extra instances share it. Budget is reserved per actual Vertex attempt; only a failed Vertex call (non-2xx, network, timeout) falls back to `GEMINI_FALLBACK_MODEL`, never malformed JSON or a schema error. Any failure yields an `unavailable` narrative and never fails the playbook. Models: `GEMINI_MODEL` / `GEMINI_FALLBACK_MODEL`.

## Web (Tavily)
"This week in the city" (`GET /v1/this-week`) uses Tavily `search` only: `search_depth: "basic"`, `max_results` 5, never research/crawl/extract. Hard caps of 25 calls/day and 600/month are checked before every call and persisted in Firestore doc `tavily_usage/<YYYY-MM>` (`QLOO_USAGE_BACKEND=firestore`), so restarts and extra instances cannot exceed them; over cap the route answers `unavailable` (`capped`), never a paid fallback. Every call logs its running count. Results are cached 7 d under tool `tavily_this_week`. `TAVILY_API_KEY` comes from Secret Manager secret `tavily-api-key` (optional; absent means `unavailable`/`no_key`). Summaries are verified by `web/verifyWeb.ts`: items need at least one entity found in the cited source, and numbers in the item text must appear in the cited title/content. All tests use fakes; one manual smoke test only, run by Prateek.

## Strategist
`POST /v1/strategist` (`{ messages, context }` + `x-session-id`) streams SSE from `strategist/run.ts`: a bounded Gemini tool-calling loop. Limits: 4 model rounds and 6 tool calls per turn, then one forced text-only answer (`stoppedEarly: true`). Every Gemini attempt reserves the narrative ceiling (`reserveAttempt`: 20/session + daily). Inputs are re-validated by `strategist/safety.ts` (12 messages, 1,000 chars, 20 context cities); the board context goes to Gemini as data. Client display names (artist, regions, city name/country, and the Without-Qloo inputs) pass `isSafeContextText` (printable, 1-100 chars, no control/bidi characters or `<>`, so "AC/DC" and "P!nk" work); an invalid city or region is dropped, only a malformed shape is a 400. Model-proposed tool args keep the strict `isSafeName`. Tools (`strategist/tools.ts`): the nine allowlisted `qloo_*` insight tools plus `get_city_playbook`, all through `QlooCaller`; unsafe or unknown calls come back as `rejected` and never reach Qloo. Events: `strategist_thinking`, `strategist_tool_call`, `strategist_tool_result` (status incl. `needs_input`, `rejected`), `strategist_message` (`unsupportedNumbers` = numbers in the answer found in no tool result or board score, using the `verifyClaims` matcher via `tokenSupported`), `strategist_error` (`CAPPED`, `UNAVAILABLE`, `ABORTED`, `INTERNAL`), then `done`. An empty model turn is `UNAVAILABLE`, never a blank answer. Without `generate` the route streams `UNAVAILABLE`.

## Without-Qloo
`POST /v1/without-qloo` (`{ artist, regions, cities }` + `x-session-id`) asks Gemini to rank the scored cities with no taste data (`withoutQloo.ts`). Accepted only if the answer is a permutation of the input after `normaliseName`; otherwise `unavailable`/`invalid`. Reserves the narrative ceiling per attempt; only `ok` results are cached (tool `without_qloo`).

## Budget
`BudgetGuard` per-session counts roll with the UTC day. Sessions whose id starts with `mcp-public-` (the public MCP demo) additionally share a daily ceiling `QLOO_PUBLIC_DAILY_CEILING` (default 400, set by `deploy.sh`). Those calls count toward, and are checked before, the global `QLOO_DAILY_CEILING` (2000), so public traffic cannot starve dashboard sessions; over it the tool answers `BUDGET` with "Public demo limit reached for today".

## Scoring calibration and backtest (Plan 5)
- `src/scoring/calibration.ts` is generated by `node dist/scoring/calibrateCli.js --in test/fixtures/calibration/*.json --version calibrated-2026-10-17 --write src/scoring/calibration.ts --report ../../docs/qloo/calibration.md` and is never hand-edited. Inputs are Tour Board recordings only, never backtest cases. The rule is documented at the top of `src/scoring/calibrate.ts`; the numbers are in `docs/qloo/calibration.md`. `test/fixtures/calibration/` holds the 4 trimmed recordings the calibration was derived from (Mac DeMarco, Khruangbin, Natalia Lafourcade, Japanese Breakfast). `calibrate.test.ts` re-derives `SCORING` from them and requires an exact match, and also runs the default-config `scoreCity` parity test.
- The scoring display (floors, thresholds, thin and close-call flags) is carried by the streamed `scoring` event and each `city_scored` city; the dashboard reads it from the stream.
- The Talent (local acts) card is a hybrid in `pipeline/localActs.ts` and `cityPlaybook.ts`: Gemini proposes up to 10 names, each is resolved with `qloo_describe` plus an exact normalised-name match, then ranked with `qloo_rank` (`localActRankArgs`). Grounding rule: a Gemini name is shown only if it resolved to a Qloo entity; unresolved names are dropped and counted (`suggestionsUnresolved`). Without Gemini, the card uses the city-popular artists only. It is not claimed to beat the generic LLM and has not been tested.
- The backtest (`src/backtest/`) shares request builders with the playbook (`artistTasteArgs`, `cityPopularityArgs`). Unavailable answers are "no answer", not a miss. `backtest/results*.json` are committed outputs; do not hand-edit.
